# TIME ECHO AI NPC 技术升级

本次升级把综合方法论落到 Godot 主版本，目标是“硬内核、软表面”：任务、证据、时间、物品和结局保持确定性；大模型负责理解自由表达、角色化台词和有限动作提案。

## 1. 数据与权限边界

- 规范事实与本轮世界状态仍由 `GameManager`、`KnowledgeManager`、`DialogueManager` 和其他本地系统维护。
- `TimeEchoContextCompiler` 为每个 NPC 生成独立认知投影，不发送完整背包、证据表、知识表或私有 flags。
- 每条可说事实带 `belief_id`、`truth_status`、`confidence` 和 `source`；玩家“持有”、当前“出示”和 NPC 已经“核验”保持不同语义。
- 角色卡运行时只保留行为与语言策略。原始 `voice` 中混合的剧情前置条件不会直接注入模型。
- 艾达按姓名、住处、职责、面孔四个锚点分阶段开放身份；未锚定阶段的角色核心不含完整姓名与职责。

## 2. 上下文编译

每轮冻结当前循环、时间、地点和 NPC 状态，依次执行：

1. NPC 身份、当前循环、可见事实和动作前置条件硬过滤；
2. 角色核心与当前场景模式装载；
3. NPC 专属信念、本轮主观记忆和最近八轮对话分区装箱；
4. 生成带优先级、TTL、最大提及次数、冷却和禁止动作的导演意图；
5. 记录装入 ID、旧循环/超额裁剪项、各分区 Token 估算和 trace ID。

trace 保存在 `TimeEchoAIService` 的本地调试环（最近 64 轮），不写入角色知识。

## 3. 生成与提交

模型严格返回：

```text
reply / action / reason / memory / referenced_ids
```

`action` 只是语义提案。Godot 收到后会：

1. 检查动作是否来自本轮硬前置条件白名单；
2. 在提交瞬间重新计算 `DialogueManager.get_actions()`，防止等待期间状态漂移；
3. 由 `DialogueManager.apply_action()` 写入权威状态；
4. 若条件变化则拒绝，不产生任务副作用；
5. 不直接信任模型的第二段自由 `memory` 写回；Godot 根据实际玩家发言与最终显示台词生成带 event ID 的当前循环主观记忆。

网络不可用、返回非法动作或输出损坏时，继续使用完整的本地规则路径。

## 4. 生成后质量门

服务端在台词进入 Godot 前执行确定性质量检查：

- 正常面对面对话中剥离虚假的“没听清 / 乱码 / 再说一遍”，但保留其余有效角色台词；
- 玩家明确询问高置信本轮事实时，回复必须覆盖相关 belief；
- 台词不能否认自己引用的已知事实，知识边界类否定事实不会被误判；
- 必要时使用 NPC 自己的已知事实保底，绝不补入全局秘密；
- `quality_guard` 随本地 trace 保存，便于统计模型原生通过率和修复率。

命令行实验台现在与 Godot 正式链路使用同型的 persona、scene mode、known beliefs、relationship、director intent、当前循环记忆和最近对话分区。审计 trace 在终端单独显示且不发送给模型。

## 5. 时间循环语义

跨循环保留：玩家知识、照片、持久日志。

循环重置：世界机关、物品、证据、普通 NPC 对话和普通 NPC 主观记忆。

如果未来设计某位 NPC 能跨循环记忆，应新增显式角色规则与独立持久集合，而不是复用普通 `npcNotes`。

## 6. 自动评测门槛

- 关键秘密泄漏率：0。
- 未满足证据链的关键动作写入率：0。
- 旧循环普通 NPC 记忆召回率：0。
- 非白名单动作提交率：0。
- 在线失败时完整流程可玩率：100%。

相关测试位于 `godot/tests/test_runner.gd` 与仓库根目录 `tests/`。
